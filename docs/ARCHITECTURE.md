# 设计说明

这份文档记录「時局圖」的关键取舍，以及 Phase 2（自动采集管线）应该怎么接。
如果只想知道怎么跑起来和怎么加数据，看 [README](../README.md) 就够。

---

## 1. 核心决策：为什么是两个时间尺度，而不是一条时间轴

第一版最容易做错的事，是把它做成一"条"时间轴：左边是去年的新闻，右边是今天的新闻，越往右越新。
这样做的结果是它退化成又一个新闻地图——因为**事件和趋势不是同一根轴上的两个位置，它们是两种不同的对象**。

| | 近事 SituationEvent | 大势 Trend |
| --- | --- | --- |
| 时间 | 一个点（`date`） | 一个区间（`since` + `horizon`） |
| 几何 | 点（印章 + 涟漪） | 折线走廊（数据），落图为一个罗盘徽记 |
| 量纲 | `severity` 1..5 | `confidence` 0..1 + `direction` |
| 生命周期 | 会被新事件覆盖、会过期 | 会持续多年，靠指标更新而不是被替换 |
| 可信度问题 | "这事发生了吗？" | "这个判断站得住吗？" |
| 更新方式 | 追加 | 修订 |

所以数据模型里两者是**并列的两个类型**，共用 `Actor` 和 `Place` 两套词汇，但不共用时间字段。
UI 上它们是两个图层，可以单独看，也可以叠加（「合觀」）。

叠加态才是这个产品的价值所在：**孤立的近事没有意义，孤立的趋势无法证伪，叠在一起时，
事件就成了趋势的采样点。** 详情面板里那句"反向张力"就是为这个目的写的——
如果一条趋势写不出什么会让它逆转，它就不是判断，是叙事。

## 2. 渲染栈：为什么是 globe.gl

| 方案 | 优点 | 为什么不选 |
| --- | --- | --- |
| **globe.gl / three-globe** | 三维球体开箱即用；弧线、涟漪、HTML 标记、标签都有现成图层；底层是 three.js，材质可以随便改 | 选它 |
| CesiumJS | 地理精度最高、支持地形与真实影像 | 为写实地球而生，要做版画风格等于跟它对抗；包体积大一个量级 |
| MapLibre GL（globe projection） | 矢量瓦片、地图生态成熟 | 仍是"地图"，投影到球面只是观感；自定义材质和弧线动画不如直接写 three.js |
| 纯 three.js 自己搭 | 完全可控 | 弧线插值、遮挡判断、HTML 标记投影这些都要自己写，Phase 1 性价比太低 |

选它的真正理由：**这个应用的视觉目标是"一颗放在桌上的旧地球仪"，不是"从太空看地球"**。
three-globe 把球体当普通 mesh 处理，我可以直接换掉 `globeMaterial` 的贴图，
这是写实型引擎不会给的自由度。

## 3. 地球贴图：为什么程序化生成

`src/globe/parchment.ts` 在浏览器里用 canvas 画出一张 4096×2048 的等距圆柱贴图。步骤：

```
羊皮纸底色 ──▶ 陈旧斑驳（90 团低透明径向晕染）
            ──▶ 纸纹噪声（1024×512 逐像素噪声，overlay 混合放大到全幅）
            ──▶ 经纬网（每 15° 细线，赤道/本初子午线加重，回归线与极圈用虚线）
            ──▶ 陆地底色
            ──▶ 国界（细墨线）
            ──▶ 陆地排线 hatch（clip 到陆地路径后斜向 45° 排线，间距 9px）
            ──▶ 海洋点刻（小尺寸遮罩 + getImageData 查表，6 万个点）
            ──▶ 海岸线（落在最上层的重墨）
            ──▶ 极区加深
另出一张灰度图作 bumpMap（陆地白、海洋黑，多次错位叠加代替 blur 滤镜）
```

这么做换来三件事：

1. **风格可控**。铜版画的质感靠排线，不靠色块。所有颜色集中在 `COLOR` 常量里，改一处就整体换季。
2. **零外部资源、零版权风险**。边界数据来自 `world-atlas`（Natural Earth 110m，公有领域，两个文件合计 163KB），
   不需要请求任何图片。整个应用可以完全离线跑。
3. **确定性**。所有随机都用 `mulberry32` 固定种子，同一个版本每次生成的地球完全一致，
   截图可以当回归基线用。

两个踩过的坑，代码里都有注释：

- **跨日界线的多边形**：俄罗斯、斐济这类地物直接连线会在图上拉出一条横贯整幅的墨线。
  解法是检测相邻点 x 跳变超过半幅就断成新子路径，并把国界/海岸线各画三遍（偏移 −W、0、+W）来缝合接缝。
- **`isPointInPath` 的性能陷阱**：最初海洋点刻用 `ctx.isPointInPath()` 逐点判断是否落在陆地上，
  复杂度退化成"点数 × 路径段数"（6 万 × 上万段），直接卡死。
  改成在小尺寸遮罩上 `getImageData` 一次、之后查表。

## 4. 视觉编码表

一张图里能编码的维度有限，分配如下，**每一项都只编码一件事**：

| 视觉通道 | 编码 | 载体 |
| --- | --- | --- |
| 印章内一个字 | 主行为体 | `.mk__seal`（沿用《时局图》以动物喻国的传统，改用一字篆印） |
| 印章外圈色 | 事件门类 | `CATEGORY_META[category].color` |
| 印章大小 | `severity` | `26 + severity * 3.5` px |
| 右上 `+N` | 还有几个参与方 | `.mk__badge` |
| 扩散涟漪 | `severity ≥ 4` 的事件 | 半径与周期都随强度变化 |
| 菱形罗盘 + 方向字 | 趋势的升降稳荡 | `DIRECTION_COLOR[direction]` |
| 罗盘外的圈数与线型 | 趋势的时间尺度 | 1y 点线 / 3y 单圈 / 10y 双圈 |
| 菱形下一排小印 | 趋势涉及的行为体（前 4 个） | `.mk__seals` |

### 4.1 被删掉的两族线

球面上曾经画两族曲线，现在一条都不画了。两次删除的理由不同。

**事件弧线（0.2.0 删）**：事件的每个关联地点都会从 `places[0]` 引一条虚线弧，
用「起点→多处」的扇形表达"这件事牵动了哪些地方"。

- 18 条事件平均分叉 2.1 条，共 **38 条**弧线，视觉噪声盖过了印章本身。
- 更根本的问题是**语义不成立**：那条弧线看起来像路径，实际只是"关联"。
  红海事件从亚丁湾扇形连到苏伊士与好望角，读起来像船这么开，但它表达的只是"两种航线选择"。
  用同一种语法去画军事、外交、贸易、气候四类异质事件，换来的是统一，代价是误导。
- 删掉之后，"牵动了哪些地点"由详情面板的「现场」列表承担：那里能标出
  起点（`origin`）/ 现场（`site`）/ 终点（`target`）的角色，信息量比一条无方向的曲线更准。

**大势走廊带（0.3.0 删）**：10 条大势的走廊折线原本逐段相连，共 **29 段**曲线，
是删掉事件弧线之后球面上唯一的线族，于是顺理成章地成了新的视觉主体。

- 两族线合计 67 条曲线时图面噪声盖过印章；只留走廊带仍有 29 条，
  在「合觀」模式下依然压着事件印章。
- 走廊带比事件弧线更值钱——它承载的是趋势的空间形态，不是单纯的关联。
  但它的信息量在**详情面板里更完整**：那里有节点顺序、角色和方向，
  而球面上的一段曲线说不出"从哪到哪、为什么这样走"。
- 于是 `corridor` 数据保留、画线取消，罗盘徽记改挂在折线中点（`corridorAnchor()`）。
  代价要如实记下：**大势从"一条带"退化成了"一个点"**——
  「大勢」模式现在只能告诉你"哪里有事"，说不出"往哪里走"。

两族线删净之后，`buildArcs()`、`ArcDatum` 和给曲线掺墨用的 `inkify()` 一并从代码里移除，
球面上不再有任何动态线条：**只剩印章、罗盘与涟漪**。

判断这条路线对不对，只需回答一个问题：这个应用是**用球面读数**还是**用面板读数**？
现在的答案是后者——球负责"哪里"，面板负责"什么、为什么、然后呢"。
如果哪天发现用户从不打开详情面板，那就是该把线加回来的时候。

### 4.2 新增一个门类要动哪些地方

2026-10-05 加了第八格「政 / 政治」。这是完整清单，按顺序：

1. `src/types.ts` — `Category` 联合类型 + `CATEGORIES` 数组。**成员**是权威定义。
2. `src/theme.ts` — `CATEGORY_META` 加一格的单字标签、名称、颜色、一句释义。
3. `scripts/lib/rules.mjs` — `CATEGORY_RULES` 加一组关键词。**位置决定判定优先级。**
4. 图例、筛选色块、印章外圈色、详情面板、时间轴刻度全部自动跟随，一行都不用改。

两个坑：

- **闸门里原本有一份手抄的门类枚举**（`scripts/pipeline.mjs`）。加"政治"时忘了同步，
  闸门立刻把 8 条 politics 事件判成"未知门类"。现在它改成从 `src/types.ts` 读了——
  Node ≥ 22.18 支持原生类型剥离，`.mjs` 可以直接 `import '../src/types.ts'`。
  这份副本本来就不该存在。
- **`CATEGORIES` 的顺序和 `CATEGORY_RULES` 的顺序是两回事，而我一开始以为是一回事。**
  写了个"顺序必须一致"的断言，结果当场发现这两张表**从来就没同过序**：
  `types.ts` 是图例的展示顺序（按语义分组：兵政交 / 财能技 / 候民），
  `rules.mjs` 是判定优先级（越"硬"越靠前：技在能前、能在财前，所以一条
  "出口管制 + 贸易"的新闻归技术而非经济）。断言现在只比成员。
  `collect.mjs` 启动时会跑；把 `category: 'politics'` 故意改成 `'politix'` 可以验证它会拦住。

**配色**：`politics` 取 `#8c3f6b`（洋红位，约 330°）。既有七色的色相分布是
4°（兵）/ 31°（民）/ 36°（财）/ 135°（能）/ 173°（候）/ 210°（交）/ 281°（技），
空得最开的就是 330° 附近——最近的两个邻居是冲突的朱砂（差 34°）和技术的紫檀（差 49°）。
试过更"像政治"的深蓝（藏青、黛），但都和外交的靛青挤在同一条色相上，
而印章外圈只有 1.5px 宽，那点差别肉眼分辨不出来。

## 5. 交互模型

- **时间游标的语义是"截至某日已知的情形"**，不是"播放一段动画"。游标右侧的事件一律不出现，
  越过游标的事件留在图上。回放只是连续推游标，用来观察事态在时间上的**堆积节奏**——
  哪些月份是密集的，哪段时间是安静的。
- **选中即转正**：点开一条近事时若当前在「大勢」模式，会自动切到「合觀」，
  并 `pointOfView` 飞到现场。选中任何东西都不该出现"我选了但它不在图上"的状态。
- **初始自转，一旦交互就永久停止**（`controls` 的 `start` 事件）。这是地球仪的礼节。

React 与 globe.gl 的接缝处理：

- 地球实例只在挂载时创建一次，数据变化走独立的 `useEffect`。所有回调塞进 `handlersRef`，
  避免父组件重渲染导致球体被销毁重建（重建一次要几百毫秒，因为要重新生成贴图）。
- 贴图在模块级缓存。React 严格模式下 effect 跑两遍，不能每次重算。
- `ResizeObserver` 挂在容器上而不是只听 `window.resize`，因为侧栏开合会改变容器尺寸而窗口没有 resize 事件。

## 6. 体积与性能

当前构建产物：JS 2.38MB（gzip 699KB），CSS 18KB。几乎全是 three.js + globe.gl + 边界数据。

已知的改进方向，按性价比排序：

1. **把地球层 `React.lazy` 拆出去**：首屏先渲染面板与骨架，地球 chunk 异步加载。
   2.3MB 里没有一字节是 UI 需要的。
2. **降低贴图分辨率**：4096×2048 的 RGBA 球体贴图约占 33MB 显存。集成显卡上可以降一档到 2048×1024
   （`parchment.ts` 里的 `TEX_W/TEX_H` 是单一出口）。
3. **边界数据按需**：只画海岸线的话 `land-110m.json` 就够了（55KB），国界那 108KB 可以省。

不做的事：不引入状态管理库（这个应用的状态就是几个 `useState`），不引入 UI 组件库（面板样式是风格的一部分）。

### 6.0 实测出来的东西（2026-10-05，本机）

这些都是跑出来的，不是查文档抄的。换网络环境后重跑 `npm run collect:probe` 重新判定。

| 结论 | 细节 |
| --- | --- |
| 13 个源可用 | 6 个英文通讯社/大报、2 个亚太、3 个中文、2 个智库，RSS 2.0 / RDF / Atom 三种格式 |
| **Nikkei Asia 停用** | item 只有 title / link / rdf:about，**没有任何日期字段**。没有日期就进不了时间序列 |
| **人民网停用** | RSS 冻结在 2025-06-05（采集时已 11992 小时前），实际已停更 |
| ReliefWeb v1 已下线 | 返回 410；v2 需要注册 appname |
| GDELT 可用但限流 | 明确回 "one every 5 seconds"；间隔 6 秒稳定 200。另外它的 DOC API 返回的是**文章**不是事件，要事件得用 15 分钟一份的 Events 2.0 原始 CSV，是另一种入库模式 |
| 联合早报 / RSSHub 公共实例 | 404 / 403，前者路径变更，后者已禁匿名 |
| ECFR / Crisis Group | 连接失败（DNS 或区域不可达） |
| Nominatim 可用 | 作为第三层地名解析；1 req/s 限速 |

一次典型采集（48 小时窗口）：

```
原始条目 423 → 超出窗口 108 → 聚合贴 4 → 未分类 108 → 无地点 12
通过 70 → 归并成 51 个事件簇（19 条并入其他簇，7 个事件由 ≥2 家独立信源报道）
```

（这是补上国家地名册之后的数字。补之前是 通过 49 / 35 个簇 / 4 个多源，见 6.0.4。）

**约九成原始条目被丢弃，这是正常的**：世界新闻里绝大多数是体育、犯罪、地方政治，
不是地缘事件。真正的信号是"丢弃原因的分列统计"——它区分了**源的问题**（超窗/无日期）
和**规则的问题**（未分类/无行为体），前者换源，后者调词表。

### 6.0.1 规则层的五个坑（都踩过，都写在代码注释里了）

1. **拉丁词必须加词边界**。忘了加，`war` 匹配上 `warning` 和 `toward`，
   85 条候选里 60 条被误判成冲突。`compileRules()` 现在自动补 `\b`。
2. **英文词要接受词形变化**。写 `troop` 匹配不到 `troops`，写 `sanction` 匹配不到 `sanctions`，
   而标题里复数才是常态。现在单数词自动展开 `(?:s|es|ed|ing)?`，
   `war` 仍然不会匹配 `warning`（`\b` 卡住了）。
3. **`US` 必须区分大小写**。加 `i` 之后它匹配英文单词 "us"（"...told us..."），
   会把一堆无关新闻锚到华盛顿。约定 `=US` 表示区分大小写。
4. **抽取只能用标题，不能用正文**。第一版用「标题+正文」，结果一篇讲提格雷冲突的文章
   顺手提到沙特、埃及、阿联酋，于是"埃塞俄比亚提格雷的冲突"被锚到了利雅得；
   一条法国学校抗议的直播贴因为正文里有 drone/war/attack 被归成冲突、强度 4。
   现在的分工：**标题定性（门类/行为体/地点），正文只写摘要**。
   代价是召回率下降——这是刻意的，错锚比漏掉贵得多。
5. **行为体锚点要按出现位置排序**。第一版按字典书写顺序返回，美国在第一行，
   于是"全世界的事都发生在华盛顿"。现在按在标题中出现的先后排，
   "North Korea launches missile after Seoul demands apology" 取朝鲜而不是韩国。
   补上国家地名册之后，这条规则从"选哪个行为体"升级成了"选标题里最早出现的那个国家"。

另外两条与归并有关：

- **簇键不能含行为体集合**。第一版把 actors 放进桶键，不同媒体提到的行为体数量不同，
  同一事件永远撞不到一起，85 条候选归并出 85 个簇——等于没归并。
  现在桶键只按门类，是否同一事件完全交给相似度判断。
- **短文本不能用 Jaccard**。Jaccard 的分母是并集，两条各 10 词的标题各自多带 2 个修饰词
  就被稀释到 0.22，而它们其实是同一件事。改用**共享词数 ≥3 且重合度 ≥0.35** 双条件。
  实测：NYT 的 "Russia strikes Kyiv bridge as German chancellor visits Ukraine" 与
  Guardian 的 "Kyiv bridge hit in further Russian drone attack as German chancellor makes
  surprise visit" —— Jaccard 0.22（判为不同事件），重合度 4/10 = 0.40（判为同一事件，正确）。

### 6.0.2 调参回路

`--sample N` 除了打印候选样本，还会打印**被丢弃的"未分类"样本**。这个功能两次证明了价值：
上面第 2 条和第 6.0.1 里的 `rebel`/`invasion`/`tornado`/`fighting`/`combat`
全是从这个清单里捞回来的——它们本来是真新闻，只因为词表没这个词就被扔了。
**没有这个回路，调规则就是盲调。**

### 6.0.4 国家地名册：把「视觉层」和「地理层」拆开

补这一层的动因是召回率。行为体表只有 **37 个精选行为体**——每个都带动物徽记和印色、
要出现在图例里——而现实新闻里的国家远不止这些。
"Ethiopia's forces retake Mekelle" 因为埃塞俄比亚不在表里被整条丢弃。

关键不是"再加 140 个行为体"：那会逼着你给 175 个国家各配一个动物徽记，图例直接爆掉。
要拆的是**两个被混在一起的概念**：

| | `data/gazetteer.actors.json` | `data/gazetteer.countries.json` |
| --- | --- | --- |
| 内容 | 37 个精选行为体 | 175 个国家/地区 |
| 用途 | **视觉层**：徽记字、印色、图例 | **地理层**：只提供名字和坐标 |
| 来源 | 人工策展 | world-atlas / Natural Earth，离线生成 |

生成器 `scripts/build-country-gazetteer.mjs` 做三件事，全都不依赖任何地理编码服务：

1. **坐标离线算**：取面积最大的那个多边形的鞋带重心。不用"所有多边形的加权平均"是有意的——
   美国含阿拉斯加与夏威夷、法国含海外省、挪威含斯瓦尔巴，平均下来会把代表点拖到奇怪的地方。
2. **跨日界线先展开经度**：斐济、俄罗斯、新西兰横跨 180°，直接用原始经度算重心会得到
   地球另一侧的结果。逐点消解 ±360 跳变后斐济落在 `-17.8, 178.0`，正确。
3. **中文国名 100% 覆盖**，并处理三类假阳性：
   - **大小写**：ASCII 国名区分大小写匹配。"turkey"（火鸡）、"china"（瓷器）、"us"（我们）
     不会误命中。代价是全小写正文匹配不到——但抽取本来就只看标题。
   - **词边界按首尾字符决定**：`U.S.` 以非单词字符结尾，尾部硬加 `\b` 会让 "U.S. envoy" 永远匹配不上。
   - **中文最长优先**：`南苏丹` 必须先于 `苏丹` 命中。实现上不靠排序，而靠
     "取标题里最早出现的那个国家，同位置取更长的名字"。
   - 另外 `中非` 被刻意排除（会命中"中非合作论坛"），只保留 `中非共和国`。

同一批数据、同一时间窗的前后对比：

| | 补国家册之前 | 之后 |
| --- | --- | --- |
| 通过条数 | 49 | **70** |
| 事件簇 | 35 | **51** |
| 多源交叉 | 4 | **7** |

顺带修好一处精度问题：`Yemen's government declares counter-offensive...` 以前锚到**利雅得**
（沙特是标题里唯一命中的注册行为体），现在 "Yemen" 在标题里出现得更早，锚到**也门**。

### 6.0.5 地名别名层：让英文标题也能落到城市

`data/gazetteer.json` 原来的键只有中文名，于是**英文标题永远匹配不到具体地点层**：
"German Chancellor in Kyiv" 找不到"基辅"（册里没有 `Kyiv` 这个键），一路退到国家层，
点落在乌克兰中部而不是首都。

改动是给每条加一个 `aliases` 数组：

```jsonc
"基辅": { "lat": 50.45, "lon": 30.52, "aliases": ["Kyiv", "Kiev"] }
```

顺带补齐了 37 个行为体首都里**缺席的 18 个**（莫斯科/伦敦/巴黎/德黑兰/新德里……），
它们以前只能靠最后一层兜底。现在策展地名册 **85 条、102 个别名**。

闸门（`pipeline.mjs`）也建了「任意名字 → 条目」的反查表，所以候选数据里直接写
`{"name": "Kyiv"}` 能补出坐标，并且会被**规范化成中文名**——球面上的地点标签才统一。

### 6.0.5.1 别名层顺带暴露的一个旧 bug

加上别名层之后，`North Korea launches ballistic missile after Seoul demands apology`
从**朝鲜**变成了**首尔**。问题不在别名，在原来的**分层短路**：

```
旧：先查 85 条具体地点 → 命中就返回；查不到才查 175 国
```

`Seoul` 一命中具体地点层就短路了，而导弹的现场是朝鲜。
一条标题里的城市**未必是事发地**，它可能只是消息来源。

修法是把两层**合并成同一个索引**，由"在标题中出现的位置"统一裁决：

```
新：所有名字（85 个具体地点 + 175 个国家）一起扫，取最早出现的那个
    同位置取名字更长的（"几内亚比绍" 优先于 "几内亚"）
    名字一样长时取更具体的（具体地点优先于国家）
```

记者把主语和事发地前置，这条启发式在实测里比"分层短路"稳得多。
同时把自动事件的 `places` 从"最多 2 个"收紧到 **1 个**——
自动抽取给一个权威现场就够了，多现场的丰富度是人工策展才该有的东西。

验证（同一批数据、同一时间窗）：

| 标题 | 改前 | 改后 |
| --- | --- | --- |
| `North Korea launches ballistic missile after Seoul demands apology` | 首尔 | **朝鲜** |
| `German Chancellor in Kyiv: "Ukraine will need our support"` | 乌克兰 | **基辅** |
| `Russian strike hits Kyiv amid Chancellor Merz visit` | 莫斯科 | **基辅** |
| `Kyiv bridge hit in further Russian drone attack…` | 基辅,莫斯科 | **基辅** |
| `Yemen's government declares counter-offensive…` | 利雅得 | **也门** |

### 6.0.6 还没解决的（按重要性）

1. **31% 的自动事件没有行为体**（只有地点）。这是拆开视觉层/地理层的必然结果：
   也门、缅甸、斐济、埃塞俄比亚都不在 37 个精选行为体里，于是印章没有徽记字，
   退化成门类字符。要不要为高频国家补进行为体表，取决于你希望图例长成什么样。
2. **摘要直接用原文 description**，中英混杂，没有改写。接 LLM 之后应该让模型写一句中文摘要。
3. **归并只在 ±1 天内生效**，跨天的同一事件会分成两条。
4. **GDELT 需要另一种入库模式**：DOC API 返回的是文章不是事件，要事件得用 15 分钟一份的
   Events 2.0 原始 CSV 转储。
5. **`places` 只取一个之后，多地点事件的信息变少了**（例如"美国在日本岛屿部署导弹"
   只留下一个点）。多地点需要的是"角色"（起点/现场/终点）判断，规则做不好，是 LLM 的活。
6. **种子数据集里没有一条 politics 事件**，所以球面上新加的那格图例点下去是空的。
   采集端能产出（一次 54 个事件里 8 条是 politics），但按规矩没有人工复核就不 promote。

### 6.1 采集（设计说明；规则版已实现，见 6.0）

优先选**结构化程度高**的源，别一上来就解析新闻正文：

| 源 | 给的什么 | 说明 |
| --- | --- | --- |
| GDELT | 全球事件流 + 地理编码 + 情绪 | 已经是"事件"形态，做近事的底噪最合适 |
| ACLED | 武装冲突事件（经核实、带坐标） | 冲突门类的黄金标准，部分需要授权 |
| ReliefWeb / UN OCHA | 人道危机与灾害 | 有稳定的 API，地理信息规范 |
| 官方声明与公告 | 一手信源 | 汇率、出口管制、演训通报这类必须回到原文 |
| 智库简报 | 大势素材 | 适合喂给 Phase 2 的"趋势命名"环节，而不是事件 |

原始响应一律先落盘存档（`data/raw/snapshots/YYYY-MM-DD/`）。
**原文快照是这套系统里唯一不可再生的资产**——模型和抽取逻辑都可以换，抓不到的历史就没了。

### 6.2 抽取（LLM 的正确用法）

让模型产出**已经定义好的 schema**，不要让它自由发挥。约定：

- 强制输出 `src/types.ts` 里的字段名，`category` 只允许 7 个枚举值；
- `places` 只允许填地名，**坐标一律由第 3 步的地名册补**——让模型生成经纬度是精度灾难；
- 强制它引用原文片段（`quote`）作为每个字段的依据，便于抽查；
- `severity` 和 `confidence` **不要问模型"这事重要吗"**（它会一律回答"非常重要"），
  改为让它回答可验证的问题：涉及多少个国家？是否有武力使用？是否有官方一手声明？
  然后由规则函数把这些答案映射成分值。

### 6.3 定位

`data/gazetteer.json` 现在有 67 条，是整条管线最便宜的杠杆：**地名册命中率决定了自动化上限**。
未命中时按顺序回退：别名字典 → Nominatim（带 User-Agent、限速 1 req/s）→ 进人工确认队列
`data/raw/unresolved-places.json`。

人工确认过的地名要**写回地名册**，这是唯一会让系统随时间变准的机制。

### 6.4 归并（最容易被低估的一步）

同一个事件当天会有 20 家媒体报道。不做归并，地球会在 24 小时内变成一团糊。

建议的簇键：`(时间窗 ±72h, 门类, 主要行为体集合, 100km 内的地点)`，
用编辑距离或句向量判断标题相似度来收口。簇内取信源等级最高的一条做代表，
其余作为 `sources[]` 挂在同一条事件上——**多源交叉本身就是可信度的来源**。

### 6.5 评分

`confidence` 由三部分构成，都可审计：

```
confidence = 信源等级（一手官方 1.0 / 主流通讯社 0.8 / 单一媒体 0.5 / 社交媒体 0.2）
           × 多源交叉系数（≥3 家独立信源 1.0，2 家 0.8，1 家 0.5）
           × 时效衰减（越接近事发越可信，超过一周未跟进则下调）
```

`severity` 用 6.2 里那组可验证问题的答案加权求和。**不要让模型直接给分。**

### 6.6 大势层：建议半自动

这是整条管线最难的部分，也是最容易做假的部分。诚实的做法是**承认事件可以自动抽取，
趋势不能**——趋势是判断，把判断自动化得到的是废话。

可行的折中：

- **自动的部分**：从事件流里做统计（滚动 90 天的门类构成变化、行为体共现网络的稠密度、
  走廊沿线的交通/价格/保险指标时间序列），把"哪里的斜率在变"算出来。
  这些是**证据**，不是结论。
- **模型的部分**：把上面的证据 + 已有趋势条目喂给模型，让它做三件事：
  提出新趋势候选、指出哪条既有趋势的指标在反向、给趋势起名和写叙述。
- **人的部分**：`direction`、`confidence`、`counterforce` 三个字段**必须人工确认**。
  它们承载的是判断，而判断要有署名。这也是版面里那句"确信 85%"的道德前提。

### 6.7 人在环路

`data/raw/` 是投放目录，`scripts/pipeline.mjs` 是闸门，这个结构已经为审核留好了位置：

```bash
node scripts/pipeline.mjs --report                                     # 每天体检
node scripts/pipeline.mjs --check data/raw/events.auto.json --kind events
node scripts/pipeline.mjs --promote data/raw/events.candidate.json --kind events
```

建议的节奏：**采集与抽取全自动**，写入 `data/raw/events.auto.json`；
**归并、评分、闸门全自动**跑一遍并把结果以 PR 形式提交；**人只审 PR 的 diff**。
CI 里已经挂了 `--report`，有 `error` 级问题就构建失败——坏数据不上线这条线，要卡在 CI 而不是靠自觉。

### 6.8 还没解决、得提前想清楚的坑

- **政治敏感性**。同一个事件在不同信源里的表述可能完全对立。这个应用的立场应该是
  "**可审计的**"而不是"中立的"：保留 `sources[]`、保留原文快照、如实显示信源等级，
  让读者自己判断。做不到这一点，"时局图"就会退化成宣传品。
- **`emblem` 字段的滥用风险**。一句话隐喻很有表现力，也很容易变成阴阳怪气。
  建议只在 `confidence: verified` 的条目上使用，且由人写。
- **时间一致性**。趋势的 `indicators` 会随时间变化，需要保留历史快照，
  否则"指标在反向"这件事永远无法被验证。这是 Phase 1 模型里唯一一处已知的结构性缺陷。
